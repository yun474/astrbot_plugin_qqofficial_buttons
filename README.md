# QQ 官Bot按钮工具

给 AstrBot 的 QQ 官方机器人做一个自己的菜单：编辑 Markdown 图文、插入蓝字快捷指令、拖动排列按钮，再用自定义指令或 LLM 调用。

**作者：云云** · **版本：2.0.0** · **AstrBot：>= 4.24.2**

仓库：[yun474/astrbot_plugin_qqofficial_buttons](https://github.com/yun474/astrbot_plugin_qqofficial_buttons)

## 功能一览

| 功能 | 当前支持 |
| --- | --- |
| 菜单工作台 | 新建、复制、保存、停用、删除菜单，JSON 导入导出 |
| 原生 Markdown | 支持几乎所有 QQ 官方文档列出的原生 Markdown 正文格式；正文直接交给 QQ 渲染 |
| 图片 | 公网 HTTPS 图片、宽高设置、尾部追加或插入正文指定位置、多图 |
| 艾特发起用户 | 正文中的 `{{at}}` 自动生成艾特标签，OpenID 从本次发起事件获取 |
| 蓝字快捷指令 | 表单生成填入输入框或直接发送标签，自动 URL 编码，插入正文光标处 |
| 自定义菜单指令 | 一个菜单绑定多个指令，保存后注册到 AstrBot 命令框架 |
| 按钮布局 | 新增行和按钮、拖动换行、位置调整、普通及点击后文字、样式设置 |
| 按钮动作 | 指令、输入框文字、链接、固定回复、菜单跳转、原生 Callback |
| 点击权限 | 所有人、管理员、指定用户 OpenID、频道身份组，受 QQ 场景能力约束 |
| LLM 调用 | 发送公开的预设；可选开启临时生成普通按钮 |
| 图片转存校验 | 群聊和 C2C 含图 Markdown 校验转存结果，明确转存错误时默认总共尝试 3 次 |
| 适配器 | `qq_official`、`qq_official_webhook`；群聊、C2C、频道、频道私信发送入口 |

“几乎所有”指**原生 Markdown 正文语法的发送能力**。插件使用 `markdown.content`，除替换 `{{at}}` 和追加独立图片字段外，不过滤 QQ 专用标签。目前没有提供 `custom_template_id` / `params` 模板消息配置。各语法能否展示、按钮能否使用，仍取决于 QQ 的会话场景、客户端与机器人权限。

## 安装与第一次使用

在 AstrBot 插件管理中通过本仓库地址安装，或将仓库放进 `data/plugins/astrbot_plugin_qqofficial_buttons` 后重载。

- 最低 AstrBot 版本为 `4.24.2`，工作台依赖 Plugin Pages。
- 使用 QQ 官方适配器，配置好机器人连接和所需的消息按钮权限。
- QQ 官方文档的 2026-04-23 更新说明已开放群聊、单聊的自定义 Markdown；频道仍需相应开通。详见 [Markdown 消息文档](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/type/markdown.html)。

打开：

```text
AstrBot WebUI → 插件管理 → QQ 官Bot按钮工具 → 按钮工作台
```

1. 选择示例菜单，或新建按钮组。
2. 填写正文，在“自定义指令”中一行写一个触发词，例如 `/插件菜单`。
3. 点“＋ 添加一行”和每行末尾的“＋ 按钮”，选中按钮后设置点击动作。
4. 保存，在 QQ 当前会话发送配置的指令。新安装示例菜单默认使用 `/菜单`。

自定义指令保存后立即注册或更新，停用、删除菜单时注销。触发词须以 `/` 开头，并与 AstrBot 唤醒前缀设置配合，避免和其他插件同名。旧菜单没有触发词时需要补填。插件不再预先注册 `/按钮`、`/qq按钮`、`/buttonmenu`；内部 `/qqbtn_action` 保留给功能按钮使用。

## 艾特发起菜单的用户

在正文写 `{{at}}`，或把光标放到正文目标位置，点击“插入艾特发起用户”：

```markdown
# 功能菜单
{{at}}，请选择下面的功能。
```

发送时自动替换为：

```html
<qqbot-at-user id="本次发起用户的OpenID" />
```

无需手填 OpenID。群聊取发起者的 `member_openid`，C2C 取 `user_openid`，频道取事件中的用户 ID。原生回调打开另一菜单时，艾特的是**本次点击按钮的人**。每次发送重新取用户，不会将上次发起者的 ID 保存进预设。

占位符仅用于**菜单正文**，不替换按钮名称、动作内容、独立图片 URL 或固定回复。无法取得发起用户 ID 时会报错。QQ 的艾特展示能力用于群聊和文字子频道；私聊虽然可以取得用户 ID，也不保证显示为可点击的艾特。工作台显示“@发起用户（预览）”。

## Markdown 与 QQ 标签速查

以下格式可以直接写进正文。普通语法参考 [QQ Markdown 文档](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/type/markdown.html)，专用标签及场景限制参考 [QQ 文本交互文档](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/trans/text-chain.html)。

### 基础排版

| 效果 | 写法 |
| --- | --- |
| 标题 | `# 一级标题`、`## 二级标题` |
| 加粗 | `**重点**` |
| 下划线加粗 | `__重点__` |
| 斜体 | `*斜体*` 或 `_斜体_` |
| 加粗斜体 | `***重点***` |
| 删除线 | `~~旧内容~~` |
| 链接 | `[打开网页](https://example.com)` 或 `<https://example.com>` |
| 有序列表 | `1. 第一项`，每项单独一行 |
| 无序列表 | `- 第一项`，每项单独一行 |
| 嵌套列表 | 子项前缩进四个空格，普通段落与列表间留空行 |
| 引用 | `> 一段提示` |
| 分割线 | 单独一行 `***` |
| 段落与空行 | 直接换行；连续空行可用实际的 U+200B 零宽空格占位 |

编辑框中的 `\n`、`\u200B` 字面文本不会由插件转换成换行或零宽字符。这里是 QQ 原生 Markdown，不承诺任意 HTML、表格或所有通用 Markdown 扩展都能在 QQ 中显示。

### 图片与位置

在正文目标位置写图片，可以插入多张：

```markdown
图片上方的文字

![菜单图 #208px #320px](https://example.com/menu.png)

图片下方的文字
```

替换为真实图片 URL，`208` 和 `320` 分别为宽、高。也可以填写工作台的图片 URL 和宽高，点“插入图片到正文光标处”；选中的正文会被替换。插入后独立 URL 字段清空，避免重复追加。只填独立图片字段时，图片放在消息末尾。

QQ 服务器需要从公网获取图片。群聊和 C2C 默认携带 `force_verify_image_resource=true`：QQ 明确返回图片转存失败或超时时，默认总共尝试 3 次，耗尽后保留错误。重试依赖接口错误信息识别；普通请求超时、发送结果未知不按图片转存错误重试。频道、频道私信不附加此参数。

### 蓝字快捷指令：填入输入框

展开正文下方的“插入蓝字快捷指令”，选择“填入输入框”，填写指令、可选显示文字和是否引用消息，再点“插入指令到正文光标处”。表单自动 URL 编码并生成标签，选中的正文会被替换。

例如点击“查看更多功能”后，把 `/插件菜单` 放入输入框，标签的可读形式是：

```html
<qqbot-cmd-input text="/插件菜单" show="查看更多功能" reference="false" />
```

QQ 文档要求 `text` 和 `show` 使用 URL 编码，正式发送建议使用表单生成的形式：

```html
<qqbot-cmd-input text="%2F%E6%8F%92%E4%BB%B6%E8%8F%9C%E5%8D%95" show="%E6%9F%A5%E7%9C%8B%E6%9B%B4%E5%A4%9A%E5%8A%9F%E8%83%BD" reference="false" />
```

| 属性 | 含义 |
| --- | --- |
| `text` | 必填，点击后填入的指令或文字，编码前最多 100 字符 |
| `show` | 可选，蓝字显示内容，省略时使用 `text`，编码前最多 100 字符 |
| `reference` | 可选，`true` 表示带原消息引用，默认 `false` |

表单填写原始中文和符号，不要预先编码；手写标签则自行编码，插件发送时不会再次编码。此标签只填入输入框，仍由用户确认发送。标签本身不注册命令：想让 `/插件菜单` 打开菜单，还要在菜单的“自定义指令”中配置它。

### 蓝字快捷指令：直接发送

表单选择“直接发送”，或手写：

```html
<qqbot-cmd-enter text="%2Fhelp" />
```

点击后直接发送 `/help`，`text` 同样需要 URL 编码，最多 100 字符，没有 `show` / `reference` 属性。按 QQ 文本交互文档，**群聊、文字子频道不支持此能力**；可使用填入输入框标签，或按平台支持情况使用键盘的“发送指令”按钮。

### 其他 QQ 文本标签

| 功能 | 格式 | 场景与说明 |
| --- | --- | --- |
| 艾特指定用户 | `<qqbot-at-user id="用户ID" />` | 群聊、文字子频道；艾特发起者直接用 `{{at}}` |
| 艾特全部成员 | `<qqbot-at-everyone />` | 仅文字子频道，需要权限 |
| 跳转子频道 | `<#channel_id>` | 仅频道，目标须在当前频道内 |
| 系统表情 | `<emoji:id>` | 仅频道，ID 参考官方 Emoji 列表；普通 Unicode emoji 可直接输入 |

### 工作台预览范围

工作台近似预览基础排版、图片和按钮，`{{at}}` 显示为示例用户。QQ 专用标签可能显示为源码，嵌套列表等复杂排版也可能与 QQ 不一致；浏览器不会实际执行蓝字指令或回调。**预览范围不限制发送语法**，最终请在目标 QQ 会话验证。

## 按钮动作与原生回调

选中按钮后，在右侧“点击动作”选择：

| 动作 | 点击效果 |
| --- | --- |
| 发送指令 | 发送配置文字，例如 `/help`，QQ `action.type=2` |
| 填入输入框 | 把文字填入输入框，用户确认发送 |
| 打开链接 | 打开网页，默认只接受 HTTPS |
| 回复固定文字 | 通过内部签名指令回复预设文字 |
| 打开另一按钮组 | 通过内部签名指令发送指定菜单 |
| 原生回调：回复文字 | QQ 推送事件，插件回执并回复，不产生用户指令消息 |
| 原生回调：打开菜单 | QQ 推送事件，插件回执并发送指定菜单，可用于多级菜单 |

固定回复、菜单跳转及原生回调需要开启“启用插件功能按钮”。回调使用 `action.type=1` 和 `INTERACTION_CREATE`，插件封装签名校验、指定用户权限检查、事件去重、回执和动作执行。管理员、频道身份组的原生回调点击限制由 QQ 执行。

- **WebSocket**：插件绑定 botpy 回调并订阅 interaction intent。已连接后才安装或热重载插件，需要重载 QQ 平台连接。
- **Webhook**：在 QQ 开放平台启用 `INTERACTION_CREATE`，确保事件投递到当前 Webhook。
- 插件卸载或重载时解绑自身处理器；其他来源的回调交给原处理器。

动作不执行任意 Python/Shell。内部功能指令为 `/qqbtn_action`，更改 AstrBot 唤醒前缀时需注意兼容性。频道身份组权限的指令功能按钮需要入站事件携带成员身份组数据。

## 给 LLM 使用

工具名为 `send_qq_official_buttons`。菜单开启“允许 LLM 调用”后，模型可通过 `preset_id` 在当前会话发送预设，正文同样支持 `{{at}}`。也可以在 AstrBot 工具管理中停用整个工具。

“允许 LLM 临时生成按钮”默认关闭。开启后只允许临时生成 `command`、`input`、`link`，不能生成插件功能动作，也不能指定其他群或用户为发送目标。

## 插件配置

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| 按钮消息承载模式 | `auto` | 优先 MD，明确提示原生 MD 未授权时回退普通正文；`markdown` 强制 MD，`content` 使用普通正文 |
| 发送前校验 Markdown 图片转存 | 开启 | 群聊和 C2C 含图 MD 使用 `force_verify_image_resource` |
| 图片转存失败时的最大发送次数 | 3 | 包含第一次发送，范围 1～10 |
| 允许 LLM 临时生成按钮 | 关闭 | 普通指令、输入框及链接按钮 |
| 启用插件功能按钮 | 开启 | 固定回复、菜单跳转及原生回调 |
| 允许 HTTP 链接 | 关闭 | 控制链接按钮；菜单图片字段仍要求 HTTPS |
| 每个按钮组最大行数 | 5 | 范围 1～5 |
| 每行最大按钮数 | 5 | 手机端建议 2～3 个 |

普通正文模式不会渲染 MD 或蓝字指令标签；独立图片字段变为图片链接，正文中的 MD 图片保留原文。`{{at}}` 仍会替换为 QQ 艾特标签。

## 数据与排查

数据保存在 `data/plugin_data/astrbot_plugin_qqofficial_buttons/buttons.json`。工作台接口使用 AstrBot Dashboard 登录态，数据原子写入，导出不包含签名密钥。正文编辑上限为 2000 字符，插入标签时也会检查长度。

| 情况 | 检查内容 |
| --- | --- |
| 正文出现、按钮缺失 | 查看 `[QQ官Bot按钮] 发送接口已返回` 日志的模式和按钮数量，确认 QQ 消息按钮权限及客户端支持 |
| 自定义指令不响应 | 菜单是否保存启用、是否配置触发词、AstrBot 唤醒前缀、其他插件同名命令 |
| 无法新增行或按钮 | 是否达到插件配置的行数或按钮数上限 |
| 图片失败 | 腾讯服务器是否可公开访问 URL、资源是否过期，查看图片转存错误日志 |
| 回调无响应 | 功能按钮开关、QQ 事件订阅及投递；WebSocket 安装后是否重连 |
| 蓝字显示为源码 | 发送模式、标签编码、场景支持和客户端；工作台显示源码不等于 QQ 不支持 |

QQ 审核、频率限制、权限及客户端表现以平台实际结果为准。插件只向当前会话发送菜单，不提供 WebUI 指定 OpenID 群发。

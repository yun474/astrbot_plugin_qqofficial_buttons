# QQ 官Bot按钮工具

把 QQ 官方 Bot 的 Markdown、图片和按钮菜单交给 LLM 使用，再配一间能拖拖拽拽的独立工作台。

**作者：云云** · AstrBot 4.24.2+

</div>

## 能干什么

- 注册 `send_qq_official_buttons` LLM Tool，让模型在当前 QQ 官 Bot 会话发送按钮。
- 默认只允许 LLM 使用你明确公开的预设，模型不能自己挑群、挑用户乱发。
- 在插件详情页提供独立的“按钮工作台”，不用手搓 JSON。
- 每个菜单可编辑 Markdown、填写公网 HTTPS 图片 URL，并在工作台即时预览。
- 每个菜单可设置多个自定义指令，例如 `/导航`、`/菜单`，保存后直接注册到 AstrBot 命令框架。
- 可拖动按钮换行，也可以用位置按钮调整顺序。
- 支持群聊、C2C 私聊、频道、频道私信。
- 支持指令、输入框文字、HTTPS 链接、固定回复、跳转到另一按钮组，以及 QQ 原生 Callback 回调。
- 支持所有人、管理员、指定 OpenID、频道身份组权限。
- 支持 JSON 导入导出。
- 内部功能按钮使用 HMAC 签名，不能靠改一段指令凭空调用别的功能。

## 安装

把本仓库放进 AstrBot 的 `data/plugins/astrbot_plugin_qqofficial_buttons`，然后在插件管理中重载。

最低要求：

- AstrBot `>= 4.24.2`，因为独立编辑器使用了 Plugin Pages。
- 平台适配器为 `qq_official` 或 `qq_official_webhook`。
- QQ 开放平台账号已经获得内嵌键盘/按钮消息能力。

如果腾讯没给你的机器人开放按钮能力，插件代码写得再漂亮也只会被接口一巴掌拍回来，这个真不是云云能隔着屏幕硬开权限的。

## 使用

安装后打开：

```text
AstrBot WebUI → 插件管理 → QQ 官Bot按钮工具 → 按钮工作台
```

工作台里可以新建菜单、编辑 Markdown 正文、图片、布局、动作和自定义指令。新安装的示例菜单默认使用：

```text
/菜单
```

在“按钮布局”里，点每行末尾的“＋ 按钮”新增按钮，点“＋ 添加一行”新增一整行。选中按钮后，在右侧“点击动作”选择“发送指令”“原生回调：回复文字”或“原生回调：打开菜单”，再填写动作内容。回调选项需要在插件配置中开启“启用插件功能按钮”。行数和每行按钮数达到插件配置的上限后，不能继续添加。

在菜单的“自定义指令”里一行配置一个触发词，例如 `/导航`。保存后会直接注册或更新 AstrBot 指令；停用或删除菜单时会注销对应指令。原来的 `/按钮`、`/qq按钮`、`/buttonmenu` 不再由插件注册。旧菜单若没有自定义指令，请先在工作台添加。触发词须以 `/` 开头，并使用机器人当前的唤醒前缀设置；若与其他插件指令同名，请换一个名称。

图片字段默认会在 Markdown 消息尾部加入 QQ 支持的图片语法。要指定图片位置，可以在正文任意位置直接写 `![说明 #208px #320px](https://图片地址)`；也可以填写图片 URL 和宽高，把光标放到正文目标位置，再点“插入图片到正文光标处”。插入后 URL 字段会清空，避免重复添加。预览是浏览器侧的近似渲染，最终效果以 QQ 客户端为准。图片地址需要公网可访问的 HTTPS URL，并由你保持长期有效。没有原生 Markdown 权限时，`auto` 模式会退回普通正文：独立图片字段会变成图片链接，正文里手写的图片语法会以原文本发送。

群聊和 C2C 发送含图 Markdown 时，默认向 QQ 传入 `force_verify_image_resource=true`。若 QQ 明确返回图片转存失败，插件默认总共尝试 3 次；所有尝试失败后会保留错误，不改发未校验的含图 Markdown。频道和频道私信仍按原接口发送。接口请求超时且发送结果未知时不会按图片转存失败重试。

### 给 LLM 使用

插件注册的工具名是：

```text
send_qq_official_buttons
```

在按钮工作台打开“允许 LLM 调用”，模型才能通过 `preset_id` 看到并发送该按钮组。AstrBot 自己的工具管理页仍可随时停用整个工具。

“允许 LLM 临时生成按钮”默认关闭。开启后，LLM 只能临时生成以下动作：

- `command`
- `input`
- `link`

临时按钮不能调用插件功能按钮，也不能指定发送目标，只能发回当前会话。

## 动作类型

| 动作 | 效果 | 备注 |
| --- | --- | --- |
| 发送指令 | 点击后立刻发送动作内容 | 可以填写 `/help` 等 AstrBot 指令 |
| 填入输入框 | 只把文字放入输入框 | 用户确认后再发送 |
| 打开链接 | 打开网页 | 默认仅允许 HTTPS |
| 回复固定文字 | 插件回复预设文字 | 使用签名指令桥，不执行任意代码 |
| 打开另一按钮组 | 发送另一个预设 | 适合做多级菜单 |
| 原生回调：回复文字 | QQ 推送 `INTERACTION_CREATE`，插件回执并回复预设文字 | 不会发送一条用户指令消息 |
| 原生回调：打开菜单 | QQ 推送 `INTERACTION_CREATE`，插件回执并发送另一菜单 | 适合无指令消息的多级菜单 |

插件故意不提供“执行任意 Python/Shell”功能。一个网页表单就能把机器人变成远程命令执行器，那不是自由，是服务器在裸奔。

## 原生 Callback 接入

本插件将原生回调按钮发送为 QQ `action.type=1`。插件通过 AstrBot 平台加载钩子绑定当前 botpy client 的 `on_interaction_create`，WebSocket 模式会在初次连接前订阅 `interaction` intent；收到属于本插件的回调后，校验签名和按钮权限、按事件 ID 去重、调用 QQ 回执接口，并执行配置的动作。其他插件的回调事件会交给原先的处理器。

如果在 QQ 平台**已经连接**后才安装或热重载本插件，需重载 QQ 平台连接，让 WebSocket 重新携带 `interaction` intent。Webhook 模式需在 QQ 开放平台的回调配置中勾选 `INTERACTION_CREATE`，且 QQ 侧实际向当前 Webhook 投递该事件。回调按钮的管理员和频道身份组点击限制由 QQ 平台执行；指定用户 OpenID 会由插件再检查一次。

插件禁用或重载时会解绑自己挂载的回调处理器。Callback 只执行工作台列出的动作，不执行任意 Python、Shell 或伪造的 AstrBot 指令事件。

## 数据与安全

数据保存在：

```text
data/plugin_data/astrbot_plugin_qqofficial_buttons/buttons.json
```

- WebUI API 由 AstrBot Dashboard 登录态保护。
- 写入使用临时文件加原子替换，尽量避免异常退出写坏 JSON。
- 内部动作带 HMAC 签名。
- 指定用户权限使用 QQ 官方接口提供的 OpenID，不是传统数字 QQ 号。
- 插件会在执行功能动作时再次检查管理员、用户和身份组权限。
- 导出文件不包含签名密钥。

## 配置

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| 按钮消息承载模式 | 自动 | 优先 Markdown，被拒绝时回退普通正文 |
| 发送前校验 Markdown 图片转存 | 开启 | 群聊和 C2C 含图消息使用 QQ 的 `force_verify_image_resource` |
| 图片转存失败时的最大发送次数 | 3 | 仅 QQ 明确返回转存错误时重试，范围 1～10 |
| 允许 LLM 临时生成按钮 | 关闭 | 建议先只用预设 |
| 启用插件功能按钮 | 开启 | 固定回复和按钮组跳转 |
| 允许 HTTP 链接 | 关闭 | 关闭时只接受 HTTPS |
| 最大行数 | 5 | 插件会钳制到 1～5 |
| 每行最大按钮数 | 5 | 手机端建议放 2～3 个 |

## 已知限制

- QQ 是否展示按钮、可用样式、审核范围和频率限制最终由腾讯平台决定。
- 频道身份组权限需要入站事件带有成员身份组数据；缺少数据时服务端二次校验会拒绝功能按钮。
- 修改 AstrBot 唤醒前缀后，内部 `/qqbtn_action` 指令可能也要跟随适配。默认 `/` 前缀可直接使用。
- 自定义指令也依赖 AstrBot 的消息唤醒与指令前缀设置；建议使用默认 `/` 前缀。
- 原生回调依赖 QQ 机器人消息按钮权限及 `INTERACTION_CREATE` 事件投递；仅在工作台预览成功不代表 QQ 已授权。
- 插件只向触发 Tool 或命令的当前会话发按钮，不提供从 WebUI 直接指定 OpenID 群发。

## 正文有了但按钮没出现

先把“按钮消息承载模式”保持为 `auto`，重载插件后发送：

```text
/菜单
```

然后在 AstrBot 日志搜索 `[QQ官Bot按钮] 发送接口已返回`。日志会显示实际使用的
`markdown` / `content-fallback` 模式、按钮数量和接口返回类型。若日志显示接口成功，QQ
里仍只有正文，通常是机器人尚未取得 QQ 开放平台的内嵌键盘/消息按钮权限；这项权限
无法由插件在本地开启。
